Only 400?

The checklist flags several configurations that will outright block a live HCX migration. What are the major red flags a consultant needs to look for during the discovery phase?

[Speaker 1]
There are three primary hardware blockers that require immediate remediation before migration. First, physical compatibility mode, RDM's raw device mappings.

[Speaker 2]
What are those?

[Speaker 1]
These are VMs configured to bypass the hypervisor and send SCSI commands directly to a physical LU on an on-premises SAN array. Because that physical SAN hardware does not exist in the AVS data center, an RDM cannot be migrated.

[Speaker 2]
Then how do you fix it?

[Speaker 1]
The consultant must coordinate a storage migration to convert the RDM into a standard VMDK file prior to using HCX.

[Speaker 2]
What about clustered applications, like older Windows Server failover clusters running SQL?

[Speaker 1]
That is the second major blocker. Virtual machines configured with a shared SCSI bus where two VMs are locking the same virtual disk file to achieve high availability cannot be migrated live using HCX vMotion. Why not?

The memory state and disk locks cannot be cleanly transferred across the WAN. It requires a negotiated maintenance window for a cold migration. You must power down the cluster nodes, set the SCSI bus sharing attribute to None, execute the cold migration, and then re-establish the cluster configuration once they boot in AVS.

[Speaker 2]
And the final blocker?

[Speaker 1]
DirectPath I O devices. This is when a virtual machine is configured with PCI passthrough to directly access a physical hardware component on the ESXi host, like a specialized GPU for rendering or a proprietary cryptographic offload card.

[Speaker 2]
Ah, and AVS doesn't have those.

[Speaker 1]
Right. AVS bare metal nodes are standardized SKUs. They do not possess those specialized physical cards.

If the VM configuration attempts to migrate with the DirectPath I O dependency, the pre-migration validation will fail. The consultant must manually remove the hardware dependency from the VM configuration before HCX will allow the migration to proceed.
