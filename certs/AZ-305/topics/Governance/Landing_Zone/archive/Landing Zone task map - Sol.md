Coverage notes:

- This task is fragmented across several documentation sets: the Cloud Adoption Framework supplies the architecture and decision guidance, while Azure management groups and Azure Resource Manager define the platform hierarchy and technical behavior.
- Architecture guidance is more useful than a single product root because the recommendation must balance policy inheritance, RBAC scope, workload archetypes, lifecycle, quotas, cost ownership, environment isolation, and operational autonomy.
- Download the Cloud Adoption Framework material first, especially the landing zone, management-group, subscription, application-environment, subscription-vending, and tagging articles. Follow with Azure management groups, Azure Resource Manager, and Azure Policy.
- The central decision rule is to use management groups for common policy and access archetypes, subscriptions as workload/platform management and scale boundaries, and resource groups for resources that share lifecycle and administration. Tags provide cross-hierarchy metadata and should not be used to recreate a deep organizational tree.
- Azure Resource Graph, Cost Management tag inheritance, Azure RBAC scope, naming conventions, resource locks, and quota planning are testable supporting topics but should remain secondary to the hierarchy and tagging design itself.
