Coverage notes:

- Application proxy is the primary documentation set for remote access to on-premises web applications and should be downloaded first. It adds Entra preauthentication and policy enforcement without opening inbound firewall ports, but it does not replace the application's own fine-grained back-end authorization.
- Global Secure Access is the primary documentation set for newer ZTNA designs. Choose Microsoft Entra Private Access when users need identity-aware access to non-web private resources or arbitrary TCP and UDP applications; unlike a traditional VPN, it can scope connectivity per application.
- Active Directory Domain Services and Windows Access control remain foundational for resources that authorize users locally through security groups, group scopes, trusts, SIDs, ACLs, NTFS or share permissions, and user rights.
- Architecture guidance is more useful than a single product root because the correct design separates four decisions: who may connect, how the user signs in, what the back-end resource permits, and how access is requested, reviewed, and removed.
- For a published application, require user assignment where appropriate, target Conditional Access to the enterprise application, and select the SSO method that matches the back end. Use KCD for Integrated Windows Authentication; use SAML, header-based, or password-based SSO only when the application supports or requires that method.
- For cloud-governed authorization to an existing AD DS application, Microsoft Entra Cloud Sync can provision group membership back to AD DS. Entitlement management and access reviews can add approvals, expiration, recertification, and lifecycle removal around those group or application assignments.
- Application provisioning is distinct from Application Proxy: provisioning creates, updates, and removes accounts or roles in the target system, while Application Proxy or Private Access provides the secured access path.
- Traditional VPN and network connectivity can make a resource reachable but do not by themselves provide application-level least-privilege authorization. Remote Desktop Services, Defender for Cloud Apps session controls, forest-trust design, PIM for Groups, and service-specific authorization remain potentially testable adjacent areas but are covered more lightly here.
