Forum-discovery note: Public AZ-305 study discussions, Microsoft Q&A, and Tech Community threads repeatedly emphasize the same design decisions: Key Vault Premium versus Managed HSM or Cloud HSM, Azure RBAC versus access policies, vault separation by application and environment, managed identity instead of a stored secret, App Configuration versus Key Vault, automated rotation and certificate renewal, network isolation, and recovery. Coverage notes:

- Azure Key Vault is the primary documentation set, but a complete recommendation also requires product-selection guidance, workload identity, cryptographic custody, lifecycle automation, networking, authorization, governance, monitoring, recovery, and resilience.
- Download Azure Key Vault and Azure security fundamentals first. Add Managed HSM or Cloud HSM when the scenario specifies single tenancy, FIPS 140-3 Level 3, key sovereignty, native HSM interfaces, or migration from an existing HSM workload.
- Separate four decisions before choosing a service: the stored object type, required hardware protection and custody, the workload's authentication method, and the rotation, renewal, revocation, and recovery lifecycle.
- Managed HSM stores only HSM-backed keys, so a requirement that also includes passwords, connection strings, or TLS certificates needs Key Vault or another complementary service. Cloud HSM targets customer-controlled IaaS-style integrations rather than Azure PaaS or SaaS customer-managed-key scenarios.
- Prefer managed identity or workload identity federation over a stored credential. Use Key Vault for material that cannot be replaced by token-based authentication, rather than treating a vault as the default answer to every credential requirement.
- Use vault topology as a security boundary: separation by application, environment, region, or tenant limits blast radius and aligns authorization scope. Prefer Azure RBAC for new designs and use PIM for privileged human administration.
- Match lifecycle automation to the object. Keys support native rotation policies, certificates can use automatic renewal with integrated issuers, and secrets commonly require an Event Grid and Functions workflow, including dual-credential rotation when availability must be preserved.
- Distinguish configuration from secrets. App Configuration stores settings, feature flags, and Key Vault references; Key Vault stores protected secret material and cryptographic objects, not general application configuration or business data.
- Design recovery and availability together: enable soft delete and purge protection, protect irreplaceable objects with supported backups, understand zone and regional behavior, and retain prior key versions until dependent data has been rewrapped or migrated.
- Azure Payment HSM, AKS Secrets Store CSI integration, App Service and VM certificate delivery, Defender for Key Vault, Azure Policy, confidential-computing key release, and service-specific customer-managed-key integrations are adjacent topics worth reviewing but should not dominate this task map.
